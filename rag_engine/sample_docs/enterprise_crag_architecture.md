# Enterprise Corrective RAG (CRAG) Architecture

## Overview
Corrective Retrieval-Augmented Generation (CRAG) is an agentic framework designed to enhance the robustness of generative language model applications by introducing self-reflective evaluation loops and adaptive retrieval strategies. Traditional naive RAG pipelines rely on a single, linear retrieval step which frequently suffers from retrieving irrelevant, hallucination-inducing chunks when queries are ambiguous, polysemous, or phrased with non-standard enterprise jargon.

## Hybrid Retrieval Layer
Enterprise CRAG utilizes a dual-channel hybrid retrieval approach:
1. **Dense Vector Retrieval**: Qdrant Vector Engine stores high-dimensional dense embeddings generated by Google Gemini models (`models/text-embedding-004`). Dense vector search captures broad semantic similarity, conceptual relationships, and cross-lingual meaning.
2. **Sparse Lexical Retrieval**: BM25 (Best Matching 25) indexing scores keyword frequency, inverse document frequency, and exact lexical matches. This guarantees precise retrieval of acronyms, error codes, unique identifier strings, and specialized terminology.

## Neural Cross-Encoder Reranking
Candidates from both the dense vector index and the sparse BM25 index are merged and deduplicated by unique document chunk identifiers. The combined candidate pool is subsequently processed through a neural Cross-Encoder model via FlashRank (`ms-marco-TinyBERT-L-2-v2`). Unlike bi-encoders that encode query and document independently, the cross-encoder performs full cross-attention across the paired query-document token sequence, generating fine-grained relevance probabilities. The top-3 reranked chunks are selected as the optimal grounded context.

## Document Relevance Grading & Active Routing
Once the candidate chunks are reranked, an agentic grading node evaluates the context:
- The LLM grades whether the retrieved text contains sufficient, factual information to answer the user query with a binary assessment (`yes` or `no`).
- **Conditional Routing Edge**:
  - If graded **yes**: The graph transitions directly to the `generate_node`.
  - If graded **no** and `rewrite_count < 2`: The graph transitions to `transform_query_node`.
  - If `rewrite_count >= 2`: The graph forces a graceful fallback to `generate_node` accompanied by an explicit warning regarding insufficient source grounding.

## Query Transformation and Guardrails
When context is judged irrelevant, the `transform_query_node` decomposes search intent, removes ambiguous phrasing, and injects domain-specific semantic keywords. The system maintains an integer guardrail counter `rewrite_count` to prevent infinite cyclic looping.
